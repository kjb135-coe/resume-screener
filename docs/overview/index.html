The headline is a range, and that is the point

Run the identical configuration four times, changing nothing. Macro-F1 lands somewhere different each time:

run 10.788
run 20.833
run 30.838
run 40.837
Axis starts at 0.75, not 0, so the spread is visible. The bars are not proportional to zero.

The noise band is 0.051. That is the width of the ruler. Any difference smaller than it has not been measured — it has been observed once. Establishing this retroactively invalidated several earlier conclusions in this project, including one whole experiment whose entire range was 0.018.

The finding that changed the design

Every model was being judged against score cutoffs fitted to one model. Models grade on different scales, so that measures calibration, not judgment.

ModelShipped cutoffsIts own cutoffsHeld out
Claude Sonnet 50.8230.8280.787
GPT-5.6 Luna0.5630.8840.861

The same model went from worst to best without a single change to the model, the prompt, or the evidence. A fixed score threshold is part of the harness, not the model.

It replaced its own architecture

It ran as three agents scoring in parallel plus a tie-breaker. Measuring each part separately showed the expensive half was the half doing nothing:

Architecturemacro-F1API calls / resume
Parallel panel alone0.788~4.0
One call alone0.821~2.0
Parallel panel + tie-breaker0.872~4.3
One call + tie-breaker0.899~2.3

The parallel panel scored worse than a single call. The tie-breaker was the part earning its keep. The architecture now does one scoring call and asks for a second opinion only when the score sits near a decision boundary — same accuracy, half the calls, 26% faster.

The human queue fell the same way, and for the same reason. Escalating used to flag a candidate for review automatically; panel disagreement turned out to be a poor predictor of a wrong answer. Flagging on distance to a decision boundary instead took the queue from 53% to 16% while catching more errors.

What this does not prove

The corpus is synthetic. All 60 resumes were generated and their labels come from the archetype each was generated from. Every number here is agreement with an intended verdict, not with a hiring manager.

The cutoffs were fitted on the same corpus they are scored against. Cross-validation makes them honest — cutoffs are chosen on 4/5 of the data and tested on the fifth — but no held-out corpus exists.

About half the errors ship unreviewed. The system is wrong on ~10% of candidates and a human sees 16%. Reviewing a sixth of a stack cannot catch most of the mistakes in it. That is arithmetic, not a tuning failure.

The bias audit found nothing, which is weaker than it sounds. Swapping only the candidate's name moved group means by at most 0.20 points against a ~0.88 noise floor. That rules out a large name effect, not a small one, and says nothing about bias a name does not trigger.

How it works

1. An agent reads your job posting and writes three scoring dimensions from it. 2. A cheap agent pulls verbatim quotes out of each resume. 3. One call scores all three dimensions against those quotes. 4. A second agent takes another look, but only when the score sits near a decision boundary. 5. A human is asked only for genuinely borderline calls.
